## 正式结果

HTTP QPS **1688.40**，有效预扣 QPS **1687.10**，平均 **49.14 ms**、P95 **93 ms**、P99 **145 ms**；MySQL 观测 TPS **136.70**（有效采样区间 51.61 秒）。

全程 147309 次尝试：147131 accepted、78 个 202、100 个读取超时。明确成功请求全部落库，100 个读取超时也找到对应订单；最终订单/归属均为 147231，库存均为 352769，无重复、超卖或取消，已投递积压/retry/DLQ 均为 0。

默认 180 秒窗口末次快照仅落库 73437 笔；扩展观测约 417.8 秒首次确认全部已知预扣落库、连续 3 次一致，最终快照约在 453.9 秒。历史自动验收保留 passed=false；持续积压、超时和 202 均如实记录，不能作为最大稳定容量。

## 2026-11-07 后续追溯

78 个 202 与发送异常逐笔对应，全部为 Broker CODE 2 / TIMEOUT_CLEAN_QUEUE，排队 200–393 ms。离线审计已停止 Broker 的完整 [0,126364614) CommitLog，441708 条记录通过 CRC；全部 147231 个正式落库订单在半消息和业务消息中可找到，78 个 pending 对应消息为 0。

结论为写入前拒绝，本地预扣未执行。4.9.7 默认重试错误码不包含 SYSTEM_BUSY，应用统一将异常返回 202，缺少拒绝终态，自动对账因此持续未决。原始 HTTP 分类与数值保持不变。[专项分析](reports/4c8g-20261104/forensics.md)
